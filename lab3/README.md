# Лабораторная № 3. Anchor Modeling

Туры, отели, авиабилеты, визы и бронирования в PostgreSQL. Airflow загружает дневные изменения, Grafana показывает отчёты на последнюю обработанную дату. [Задание](https://docs.google.com/document/d/1d9BKP5TZv4ZZ1mQ2JuNxYjxUB4We7PJI/edit)

## Запуск

Нужны Docker с Compose, `make` и свободные локальные порты `3003` и `8082`. Из каталога `lab3` выполните:

```sh
make demo
```

При первом старте PostgreSQL создаёт модель и три учебных среза. Команда запускает DAG для каждого среза по порядку и повторяет последний день. После `PASS` стек остаётся доступен. Повторный запуск сохраняет историю.

- [Бронирования](http://127.0.0.1:3003/d/lab3-bookings) · [Отели](http://127.0.0.1:3003/d/lab3-hotels) · [Визы](http://127.0.0.1:3003/d/lab3-visas). Для просмотра Grafana вход не нужен, администратор — `admin / admin`.
- [Airflow · DAG и логи](http://127.0.0.1:8082/dags/lab3_anchor_load/grid). Логин и пароль — `admin / admin`.

`make report` выводит SQL-отчёты. `make check` проверяет историю, отчёты, повторную загрузку и откат ошибочной пачки внутри транзакции. `make stop` оставляет данные в томах.

Для существующего Podman с Docker-совместимым сокетом используйте тот же Makefile, например `DOCKER_HOST=unix:///путь/к/сокету make COMPOSE=docker-compose demo`.

## Сценарий защиты · 3–4 минуты

1. Откройте Airflow, выберите три запуска `demo_load` и сравните число новых ключей и версий в логах задачи `apply_source_day`. В запуске `demo_replay` покажите `already_applied` и ноль новых версий.
2. В [«Бронированиях»](http://127.0.0.1:3003/d/lab3-bookings) покажите число броней, стоимость услуг на дату брони, популярные направления и ступени цены тура № 1. В терминале выполните `make report`. У брони № 3 исходный тур — № 3, после переноса — № 4.
3. В [«Отелях»](http://127.0.0.1:3003/d/lab3-hotels) покажите распределение ночей по месяцам. В [«Визах»](http://127.0.0.1:3003/d/lab3-visas) покажите клиентов с просроченными визами и сравните с продлением визы № 10 в SQL-отчёте. Дата среза видна на первом дашборде.

## Модель и загрузка

- Шесть таблиц якорей содержат только бизнес-ключи. Справочники лежат в `anchor`, входные срезы — в `stg`. У каждого изменяемого свойства и каждой связи отдельная типизированная таблица. Маршрут учебного тура содержит один перелёт и одно проживание, виза привязана к брони клиента.
- DAG ежедневно обрабатывает завершившийся день UTC. При ручном запуске можно передать `{"load_date":"ГГГГ-ММ-ДД"}`. Сначала добавляются ключи, затем версии. Изменение закрывает старый интервал накануне новой даты. Закрытие и открытие интервалов, журнал дня и новые ключи фиксируются одной транзакцией.
- День источника после загрузки считается опубликованным. Повтор пропускается. Нарушенный порядок останавливает запуск. День без входных строк завершается без записи в журнал. Пропуск строки во входном дне означает отсутствие изменений.
- Первая запись связи брони с туром соответствует дню создания брони. При переносе отчёт сохраняет исходную стоимость. Цена пакета складывается из перелёта и тарифа отеля за число ночей. В условии цена визы отсутствует. Загрузка отелей показывает плановые ночи по действующим маршрутам с исключением дня выезда.
- В визовом отчёте маршрут и виза определяются на дату вылета. Для будущих рейсов берётся версия, известная на дату среза. Из этой версии берётся фактическая дата истечения. В день истечения виза ещё считается действующей. Дашборд включает дату среза и следующие 29 дней.
