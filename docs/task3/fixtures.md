# Исполняемые фикстуры

Оригиналы в `docs/assignments/` неизменны. В `data/task3/` лежат исполняемые копии
Extended JSON с тремя исправлениями:

| Источник | Исправление | Причина |
|---|---|---|
| `restaurants.json` | Объект помещён в массив, файл назван `restaurant.json` | Формат загрузки и имя коллекции из условия |
| Restaurant `_id` | `n857785vnh4n458nrf` → `ef8c42c14b7518a4aebec107` | Исходный ID не является ObjectId; использован `orders.restaurant.id` |
| Order `client.id` | `727a81ce4a8cd1420741e25e` → `727a81ce9a8cd1920741e258` | Ссылка на существующего клиента |

Прочие значения сохранены. `$oid` и `$date` декодируются в BSON-типы; ссылки
`client.id` и `restaurant.id` остаются вложенными. Расхождения dish ID и арифметика
cost/payment не исправлены: бизнес-расчёты заказа не входят в задание. JSON-пример
содержит `menu` и `update_time`, DOCX — `address`; адрес не выдумывается.

Seed с majority-подтверждением добавляет только отсутствующие `_id` до первого
снимка и не заменяет изменённые документы. Исправленные ссылки позволяют показать
SQL JOIN клиентов и заказов; отдельной бизнес-витрины ресторанов нет.
