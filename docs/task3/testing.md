# Проверки

[Демонстрация](../demo.md) выполняет три DAG и проверяет их результаты. Полный набор
ниже дополнительно проверяет ошибки, сбои и реальное истечение образов MongoDB и oplog.
Он использует отдельный проект без портов на хосте и уникальные тестовые базы.

```sh
docker compose -p bda-task3-tests -f tests/compose.yml build runner
docker compose -p bda-task3-tests -f tests/compose.yml up -d --wait --wait-timeout 90 mongo pg
docker compose -p bda-task3-tests -f tests/compose.yml exec -T mongo mongosh --quiet --file /dev/stdin < mongo/task3-init.js
docker compose -p bda-task3-tests -f tests/compose.yml run --rm -e TASK3_SLOW_TESTS=1 runner -m unittest discover -s tests -v
docker compose -p bda-task3-tests -f tests/compose.yml stop mongo pg
```

Прогон занимает несколько минут. Без `TASK3_SLOW_TESTS=1` медленный тест
пропускается. Он меняет retention только тестовой MongoDB и создаёт до 256 МиБ
вспомогательных записей. Это не измерение допустимого срока простоя CDC.
Остановка сохраняет тома; существующий демонстрационный стенд не сбрасывается.

| Проверка | Что проверяется |
|---|---|
| SQL и задание 1 | Аудит шести таблиц, CRUD/COPY/TRUNCATE, образы строк, откат и ошибка аудита; январская витрина и повтор |
| Задание 2 | Настоящие операторы и PostgresHook: поля CSV, повтор, замена, пустая таблица; откат при отсутствии файла или поля и ошибке COPY |
| BSON | Точные байты и токены, полные образы, типы, недоступная JSONB-проекция, SQL JOIN фикстур |
| Снимок | fsync и заблокированный писатель, anchor до сканирования, одна публикация, лимиты, потеря блокировки, откат и исход commit |
| Поток | Быстрые изменения, replay, аварии до/после commit, лимиты, сетевой отказ и SQL timeout |
| Восстановление | Реальное истечение образов и oplog, сохранение checkpoint, ручной снимок и один `gap`; запрет смены источника |
| Демосценарий | Владение блокировкой, отказ публикации, ручное восстановление, привязка активного источника и конкурентный запуск |

`tests/probe_handoff.py` отдельно проверяет передачу от снимка к потоку.
`tests/probe_restart.py` требует рестарта **тестовой** MongoDB после `RESTART_READY`
в течение 40 секунд и проверяет откат снимка. Обычный стенд для этого не используют.

Проверено 24 октября 2026 на Ubuntu 24.04 AMD64: Docker 29.9.2, Compose 5.6.1.
Архив на `08d6cb2` запущен штатной командой на пустом Docker без кеша,
правок и подмены PyPI: первый запуск — 272 с, повтор — 38 с.
Все 10 запусков DAG и 26 задач успешны; эпоха, источник и прежняя история Mongo сохранены.
Полный набор с `TASK3_SLOW_TESTS=1`: **25 тестов за 314,844 с, без пропусков и ошибок**,
включая истечение образов MongoDB и реальное усечение oplog. Все 52 файла остались неизменными.
Полный набор запускался после демонстрации, с уже скачанными образами.

Проверки не доказывают непрерывное владение fsync между двумя замерами: известный
unlock/relock требует отмены снимка. HA, бессрочное хранение истории, длительная работа
по расписанию и приёмка преподавателем не проверены.
