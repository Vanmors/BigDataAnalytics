# Демонстрация заданий 1–3

Нужны Docker с Compose для Linux-контейнеров, интернет и свободный порт 8080. Скачайте
репозиторий, откройте терминал в его корне и выполните одну команду:

```sh
docker compose -f compose.demo.yml run --build --rm demo
```

Первый запуск собирает образ, готовит базы и данные, публикует начальный снимок
MongoDB и выполняет три настоящих DAG. Настраивать `.env`, ставить Python или
запускать команды внутри баз не нужно. Дождитесь `PASS` и сводки проверок:

| Задание | Что проверяет команда |
|---|---|
| 1 | Январская витрина: 195 заказчиков, 704 заказа, расходы 8 802 285,00 и комиссия 880 228,50 |
| 2 | По 10 строк в трёх таблицах `external_source` |
| 3 | SQL-аудит INSERT, UPDATE, DELETE, TRUNCATE; Mongo insert, update, delete; повтор загрузки без дублей |

Откройте [Airflow](http://127.0.0.1:8080), логин и пароль — `airflow`.
Покажите успешные запуски:
[task1](http://127.0.0.1:8080/dags/task1_customer_report_mart/grid),
[task2](http://127.0.0.1:8080/dags/task2_external_source_ingest/grid),
[task3](http://127.0.0.1:8080/dags/task3_mongo_cdc/grid).
Результаты проверок и логи — в терминале. Даты нужны для январской витрины.

Для повторного показа выполните ту же команду. Она сохраняет историю и пропускает
начальный снимок при `active`. При `needs_manual_rebaseline` показ останавливается:
нужно [ручное восстановление](task3/operations.md), а не удаление томов.

После показа остановите стенд; данные и история останутся:

```sh
docker compose -f compose.demo.yml stop
```

Полные проверки, включая реальное истечение образов документов и oplog, запускаются
[отдельно](task3/testing.md). `PASS` демонстрации не заменяет этот набор тестов.
